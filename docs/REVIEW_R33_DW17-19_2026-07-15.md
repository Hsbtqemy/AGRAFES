# Revue adverse — D-W17 / D-W18 / D-W19 (couper généralisé · ✕ retirer · ＝ rattacher)

**Méthode :** 6 finders (une dimension chacun : `_performCellSplit`, résolveur+picker, ✕,
＝ async, gating grille, cycle de vie) → 2 réfutateurs adverses par finding. **17 findings
bruts** ; recoupés **à la main au code** (le filtre du workflow n'est pas de confiance : un
vérificateur qui meurt renvoie `verdicts: []` et se fait passer pour « réfuté »). Ci-dessous
les **confirmés**, groupés par racine et classés.

---

## G1 — MAJEUR (décision de design) · ✕ et ＝ ne sont **pas** des inverses propres

Racine : un lien **rejeté** (D-W18) occupe l'index unique `(pivot, target)` (mig 008) **mais
est invisible** dans la projection ET `cell_links` (F8). Conséquences en chaîne :

- **＝ ne peut pas défaire un ✕.** Après avoir rejeté la traduction (P→T), la cellule redevient
  ∅ ; ＝ pour re-poser T → `createAlignLink(P,T)` → **409** « … already exists » (message **brut
  anglais**, non actionnable). Le lien rejeté bloque la re-création. (`_performAttach`, ~l.1242)
- **« Réversible en Révision fine » est faux** pour le cas courant : un lien rejeté qui était le
  **seul** de son pivot (cellule → ∅) n'apparaît dans **aucune collision** → le panneau
  Collisions ne le montre pas → pas de ré-acceptation possible là. Le toast promet une
  réversibilité qui n'existe pas. (`_performCellRemove`, toast)
- **Clash invisible aux gardes.** La garde `clash` de `resolveCellSplit` et l'`alreadyLinked` de
  ＝ n'inspectent que la matrice **visible** → un lien rejeté sur le voisin/la cible échappe → le
  `create` moteur lève un **409 brut** (pas la traduction FR actionnable de `_performCellMerge`
  T7). (`_performCellSplit` ~l.809, `_performAttach`)

**À trancher :** (a) ＝/`_performAttach` **dé-rejette** un lien rejeté existant (`resolveCollisions`
`unreviewed`) au lieu de créer — ＝ redevient l'inverse exact de ✕ ; **et/ou** (b) traduire le
409 en message FR renvoyant vers la Révision fine (comme T7) ; **et/ou** (c) reformuler le toast
de ✕ pour ne pas surpromettre. Recommandé : (a)+(b).

## G2 — MAJEUR · Le `close()` capturé, rappelé après un `await`, clobbe un modal **rouvert**

Tous les modals (`_openPickerShell` + les choosers ↺/✕ + le picker ＝) capturent leur `close()`
dans une closure. Un `perform*` (ou le `catch`/fetch async) rappelle ce `close()` **après**
l'await. Séquence : ouvrir le modal → OK (write en vol, `okBtn.disabled` mais Escape actif) →
**Échap** (`close()` : `_cutBusy=false`, `_closeCutModal=null`) → ouvrir **un autre** geste (permis
car `_cutBusy=false`) → l'await résout et rappelle le `close()` **périmé** → il écrase
`_closeCutModal` (le nouveau modal n'est plus fermable par `dispose()` = **fuite F4**) et
`_cutBusy=false` (**réentrance**). (`AlignMatrixView.ts` : `_openPickerShell` l.602, `_openAttachPicker`
l.~1289, choosers.)

**Fix :** rendre chaque `close()` **propriétaire** — `const close = () => { if (this._closeCutModal
!== close) return; … }`. Un `close()` périmé devient un no-op.

## G3 — MAJEUR · `_performCellSplit` : robustesse d'écriture inférieure à Fusionner/↺

- **Garde de commit partiel incomplète** (l.778) : `if (res.applied > 0)` — alors que
  `_performCellMerge` (l.969) et `_performCellUncut` (l.1099) testent `|| res.deleted > 0`. Sur un
  **déplacement** (batch = `[delete]`), un commit partiel (ancien sidecar) où le delete a pris
  (`deleted=1, applied=0`) tombe dans la **compensation**, qui supprime le lien **créé** → l'original
  est supprimé ET le créé aussi → **cible orpheline (perte)**. Fix : `res.applied > 0 || res.deleted > 0`.
- **Compensation qui avale les échecs sans resync** (l.785-787) : `catch { /* leave for resync */ }`
  mais **aucun** `_reloadPreservingScroll` ne suit → un delete de compensation qui échoue laisse un
  **lien créé orphelin** invisible + UI désynchronisée. Fix : suivre `compensated` et resync, comme
  le `catch` (l.810-824) le fait déjà.

## G4 — MAJEUR · ＝ sur un lien **coupé** : fenêtre périmée projetée sur la nouvelle cible

Le bouton ＝ est offert dès `c.links.length <= 1` (`alignMatrixGrid.ts` l.77) — donc aussi sur une
cellule à **un lien coupé** (`char_start != null`). ＝ → `retargetAlignLink({link_id, new_target})`
change la cible **mais conserve** `char_start/char_end` → la **mauvaise tranche** de la nouvelle
cible est projetée (fenêtre `[0,6]` d'un texte, appliquée à un autre de longueur différente).
✕ et ⭙ imposent déjà « ↺ d'abord » sur un lien coupé ; ＝ a perdu cette garde.

**Fix :** exclure les liens coupés — `attachBtn` gated sur `c.links.every(l => l.char_start == null)`,
et refus dans `_openAttachPicker` (toast « ↺ d'abord »), par symétrie avec D-W18.

## G5 — MAJEUR · Cellule ∅ qui **porte** un lien : ni ↺ ni ✕ → impasse

Une cellule peut lire `status=empty` en **portant** un lien (fenêtre coupée qui tranche à vide,
`char_start=3/char_end=3` — cas R6a déjà testé). La branche `empty` de la grille (l.104) ne rend
que `ntBtn` + `mergeBackBtn` + `attachBtn` — **pas** `uncutBtn` ni `removeBtn`. Le lien est donc
**inannulable et irretirable** depuis la grille (∅ lui-même est refusé, `c.links.length===0`).

**Fix :** ajouter `${uncutBtn}${removeBtn}` à la branche `empty` (ils se gardent seuls sur les liens).

## Mineurs confirmés (correctifs bon marché)

- **⭙ (branche ok) non gardé sur `hubUnitId`** (l.129) contrairement à `mergeBackBtn`/`attachBtn` →
  offert-mais-échoue si un hub_unit_id est nul. Fix : `&& r.hubUnitId != null`.
- **＝ picker : candidat en conflit non honoré** — le composant marque la cible actuelle « ⚠ déjà
  lié » mais le wiring câble **tous** les `.prep-align-picker-cand` ; la choisir = no-op annoncé
  « ✓ re-ciblée ». Fix : ne pas câbler (ou désactiver) les candidats `data-conflict`.
- **✂ couper à cheval sur une cellule d'un seul mot** (« Yes. ») : le bouton s'affiche (aucun test
  de viabilité en grille), le modal mène à « tout partirait » / rien de cliquable. La garde « un
  seul mot » de l'ancien `resolveStraddleCut` a été **perdue** en D-W17. Fix : gater le bouton sur
  `viableCutOffsetsIn(...).length > 0` pour un lien unique.
- **`buildCellSplitPanelsHtml` : marqueur de frontière ‧ perdu si `target_text_raw` commence par
  une espace** (l.585) — `boundaryBefore` est posé sur `j===0`, mais le token j=0 (espace) est
  **sauté**, donc la frontière d'unité devient **non cliquable** (on ne peut plus « couper après le
  point » là). Fix : poser `boundaryBefore` sur le **premier mot rendu** du lien i>0.
- **F1 non re-vérifiée après l'await dans `_performCellRemove`** — le commentaire dit le contraire
  (la vérif est **pré**-await). Pas de corruption (le reject part sur la bonne conn), mais commentaire
  faux. Fix : corriger le commentaire ou re-vérifier post-await.
- **`_loadMatrix` sans garde `_cutBusy`** — « Charger » / le select famille ne sont pas gelés pendant
  un modal ouvert (seul `_runAlign` les gèle) ; l'overlay couvre la barre mais la discipline manque.
  Fix : early-return de `_loadMatrix` si `_cutBusy`, ou désactiver les sélecteurs à l'ouverture d'un modal.

## Réfutés / non retenus

- Divers doublons de G1 (le même 409 rejeté vu par 3 finders) — fusionnés.
- Craintes de perte de données sur `_performCellSplit` **hors** ancien-sidecar : l'atomique (1.6.54+)
  roule tout en arrière (`applied=0, deleted=0`) → compensation correcte ; G3 ne mord qu'en legacy,
  mais l'incohérence avec Fusionner/↺ justifie l'alignement.

  *(test : partiel `deleted:1` → resync, pas de compensation)*
- **G4** → `attachBtn` exclut les liens coupés (`char_start` nul) + garde dans `_openAttachPicker`.
  *(test grille)*
- **G5** → la branche `empty` de la grille porte `↺` + `✕`. *(test grille)*
