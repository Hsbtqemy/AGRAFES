# E-2 — accessibilité : gestion du focus et navigation clavier

**Arrêté sur** — structure tabulaire ARIA de l'audit d'alignement (item 4), commit `1306b7d`, 19 mai 2026.

## Contexte

**Aucun reliquat.** Le corps du commit d'arrêt est explicite : il « clôt le dernier point
ouvert du chantier E-2 (accessibilité) ».

Le point avait été refait proprement après le revert d'une première tentative en
`role="grid"` (commit `85c488d`, la veille). La liste des liens d'alignement à réviser
(`AlignPanel #align-bitext-body`) expose désormais une structure tabulaire ARIA complète :
`role="table"` sur le conteneur avec `aria-label`, retiré sur l'état vide ; `role="row"`
sur les lignes `.prep-align-row` ; `role="cell"` sur chaque cellule ; les picker-rows de
reciblage rendues en mode ligne de table (`_pickerRowHtml` prend un paramètre
`asTableRow`), pour que le conteneur n'ait que des enfants `row` valides.

Le choix de `role="table"` plutôt que `role="grid"` est délibéré et vaut d'être retenu :
`grid` impliquerait le pattern de navigation clavier en grille (flèches cellule à cellule),
qui n'est pas implémenté. `table` expose la structure aux lecteurs d'écran sans promettre
une interaction absente. `asTableRow` reste `false` pour les autres appelants de
`_pickerRowHtml` — vues famille en `<table>` HTML natif, liste d'orphelins — où aucun rôle
n'est requis.

Attention à l'homonymie : le code `E-2` désigne aussi, dans
`docs/AUDIT_2026-03-26.md` ligne 367, un item sans rapport (« extraire le client sidecar
en `packages/shared/sidecarClient.ts` ») — celui-là a été absorbé par U-01
(`shared/sidecarCore.ts`, clos). Le E-2 de cette fiche est le sprint accessibilité de
`docs/BACKLOG_PREP_AUDIT.md` §Sprint E.
