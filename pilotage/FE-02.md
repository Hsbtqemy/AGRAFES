# FE-02 — fuite d'écouteurs, puis divergence du miroir coarse-grain

**Arrêté sur** — miroir coarse-grain aligné value-based sur `parent_n: null`, commit `dfa73ed`, 2 juillet 2026.

## Contexte

**Aucun reliquat.** Le tracker porte `✅ corrigé` (P1-9).

Deux choses portent ce code, à ne pas confondre en reprenant.

Le finding d'origine (audit du 28 juin) : `buildUI` dans `tauri-app` n'avait pas de
disposer, les trois écouteurs `document` s'accumulaient à chaque remontage de l'Explorer.
Fix : `buildUI` retourne un disposer (helper `onDoc` qui trace les écouteurs), appelé par
`disposeApp` au démontage. `buildUI.ts` / `app.ts`, `tsc` et 81 tests app verts.

Le commit d'arrêt, lui, traite un second défaut re-signalé sous le même code par
`docs/AUDIT_BRANCHE_REFONTE_2026-07-02.md` : le miroir `coarse_grain.py` ↔ `coarseGrain.ts`
divergeait sur un `parent_n` explicitement `null`. Python détectait le régime ancré par
**présence de clé** (`"parent_n" in meta`) et groupait via `meta.get("parent_n", n)`, si
bien qu'un `{"parent_n": null}` tombait dans un méga-bloc de clé `None` ; le TypeScript,
plus sain, détecte par **valeur non-nulle** et dérive des singletons. Python a été aligné
sur le TS aux deux sites. Au passage, `STRUCTURAL_ROLES` côté TS est passé de `Set`
mutable exporté à `ReadonlySet` — un défaut de module partagé ne doit pas être mutable,
et `.add()` devient une erreur de compilation, miroir du `frozenset` Python.

Pas de producteur actuel de `{"parent_n": null}` : c'était un piège latent, pas un bug
observé. Tests miroir des deux côtés, RED prouvé côté Python.
